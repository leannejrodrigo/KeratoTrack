# KeratoTrack

> **KeratoTrack is an educational and research project. It is not a clinically
> validated medical device.** It must not be used to diagnose, monitor or make
> treatment decisions about any eye condition. Questions about your eyes belong
> with a qualified eye-care professional.

KeratoTrack is a personal portfolio and research project about keratoconus, a
condition in which the cornea thins and changes shape. It is built by a
final-year Computer Science student as a way to learn software engineering and
AI/ML engineering carefully, in a domain where care matters.

## Two separate components

| | Patient Companion | Research Laboratory |
|---|---|---|
| **Folder** | [`companion/`](companion/) | [`research/`](research/) |
| **Purpose** | Help people organise and understand their own eye-health records | Investigate how machine-learning models behave on corneal images and clinical measurements |
| **Works with** | Information the user enters, and clearly labelled synthetic demonstration data | Research datasets, once licensed and audited |
| **Output** | The user's own records, charts and summaries | Experimental results |
| **Audience** | People with keratoconus | Researchers and technical readers |

**The two are deliberately kept apart. Research model predictions never appear
in the patient-facing application, and research code never reads Companion
records.** See [`docs/safety-boundaries.md`](docs/safety-boundaries.md).

## Current status

**Companion MVP (C1–C4) and research integrity infrastructure implemented,
awaiting review** (2026-11-07).

- **Patient Companion:** a local-first web app with Overview and My Eyes.
  It stores synthetic practice data only, in the browser, and charts it with
  full provenance. JSON export and import and delete-all are already in place.
- **Research Laboratory:** a Python package for synthetic datasets,
  dataset audits, frozen patient-level splits with manifests, a guarded
  test-set evaluator with a chained access log, missing-data mechanisms,
  calibration metrics and static reports. **No real dataset has been used,
  no model has been trained and there are no results.** The literature review
  (R0) and dataset licence check and audit (R1) have not started.

Nothing has been deployed. See [docs/development.md](docs/development.md) to
run it.

## Planned technologies

These are the approved directions. Each library is confirmed, with its reason
recorded, when it is first installed.

| Area | Direction (installed libraries are recorded in [ADR 0009](docs/decisions/0009-first-libraries.md)) |
|---|---|
| Companion: application | React, TypeScript and Vite |
| Companion: storage | Local-first: data stays in the user's browser (IndexedDB), behind a storage interface. No backend server in the initial version |
| Companion: charts | React-rendered SVG, using D3 only for the maths (scales and line shapes) |
| Companion: data exchange | JSON as the complete export and import format. CSV may be added later as an extra export |
| Research | Python, pandas, NumPy and scikit-learn, with PyTorch when image models begin |
| Research: reports | Static HTML and Markdown reports generated by scripts. The interactive Research Laboratory interface comes later |
| Testing | Vitest and Playwright (Companion), pytest (Research) |

**Browser storage is not a backup.** Data kept in the browser can be lost if
browser data is cleared, the browser removes it to free space, or the device is
lost or replaced. Users will need to export their records regularly to protect
against data loss.

Candidate libraries named in the design specification (for example a database
helper and a validation library) are evaluated when they are needed. A backend
(such as FastAPI) may be evaluated for any future deployed version. The
preference throughout is for free and open-source tools.

## Roadmap

The roadmap is provisional. Each phase starts only after the previous one has
been reviewed and approved.

| Phase | Focus | Status |
|---|---|---|
| P0 | Foundations close-out: align documents, licence, repository protections | Done, awaiting review |
| **Patient Companion** | | |
| C1 | Application foundation: design tokens, navigation, core components, automated checks | Implemented, awaiting review |
| C2 | Data model and storage: validated schema, local storage, separate synthetic demo storage | Implemented, awaiting review |
| C3 | Measurement management: add, edit, delete, validation | Implemented, awaiting review |
| C4 | Measurement charts and tables, with provenance (synthetic data). **MVP checkpoint** | Implemented, awaiting review |
| C5 | Appointments (including a personal question list) and treatment records | Not started |
| C6 | Educational library and glossary | Not started |
| C7 | Data management: JSON export and import, deletion | Partly done: export, import, delete-all |
| C8 | Quality and accessibility testing | Not started |
| **Research: decision stage** | | |
| R0 | Systematic literature review: is the research question still open and worth pursuing? | Not started |
| R1 | Dataset licence and provenance check, then a reproducible dataset audit: is the dataset suitable and permitted for this use? | Not started |
| **Research: conditional on R0 and R1** | | |
| R2 | Data preparation: identifier checks, frozen patient-level splits, leakage tests | Tooling built and tested on synthetic data only; not applied to any real dataset |
| R3 | Baseline experiments | Not started |
| R4–R6 | Computer vision, multimodal and robustness experiments | Not started |
| R7 | Calibration, uncertainty and reliability analysis | Not started |
| R8 | Research reporting | Not started |
| **Optional** | | |
| — | Real-data safeguards (encryption, backup and recovery) before any real health data; a public demo using synthetic data only | Not planned yet |

**The research phases are conditional.** R0 and R1 end with a documented
decision to continue, change dataset, change direction or stop. Phases R2 to R8
go ahead only if that decision supports them, and each later phase may be
narrowed or changed by what earlier phases find. Neither positive results nor a
publication is assumed; negative or inconclusive findings will be documented
too.

No dataset is downloaded until its licence, provenance and permitted use have
been checked.

## Data

This repository contains no patient data and no research datasets.

- Research datasets, patient identifiers and patient-to-split assignments are
  stored **outside** this repository, in a folder set by an environment
  variable. They are never committed.
- Only non-identifying metadata, such as dataset versions, split versions and
  checksums, may be committed.
- Identifiable patient data must never be committed. Screenshots and public
  demonstrations use synthetic data only.
